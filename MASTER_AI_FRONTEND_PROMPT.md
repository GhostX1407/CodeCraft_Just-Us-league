# MASTER SPECIFICATION PROMPT: NEXT-GENERATION LIVING HEALTHTECH INTERFACE
### Universal Architectural Prompt for Autonomous Coding Agents & Senior Frontend Designers

> **How to use this prompt:**
> Provide this prompt along with your project's `README.md`, `PRD.md`, or architecture specification. This prompt directs the agent to completely reimagine and implement an ultra-advanced, non-generic, calm, silent-vibe HealthTech interface tailored specifically to your project's problem statement.

---

```markdown
# NEXT-GENERATION HEALTHTECH FRONTEND — COMPLETE INTERACTION & UI/UX REIMAGINATION

You are an elite **HealthTech Product Architect, Interaction Designer, Creative Technologist, and Motion Systems Engineer**.

Your objective is **100% FRONTEND ARCHITECTURE & DESIGN**.
The backend, database, and APIs are developed and maintained separately. You must consume and represent the system's real-time state, data contracts, and APIs with mathematical accuracy while completely transforming how humans experience the interface.

---

## 1. ABSOLUTE LAW — PRESERVE FUNCTIONALITY, REINVENT THE EXPERIENCE

1. **Zero Functional Regression:** Every route, form, parameter, subscription, API command, and status transition must remain 100% functional.
2. **Never Create Fake Logic:** Do not invent mock computations that bypass existing backend contracts. If the backend produces a capability score, countdown, or routing status, consume and reflect it faithfully.
3. **Complete Visual & Spatial Freedom:** You have total freedom to completely discard traditional web templates, layouts, component arrangements, and navigation patterns to create the interaction paradigm the medical problem truly demands.

---

## 2. SOURCE OF TRUTH: EXTRACTING THE PROJECT'S CLINICAL DNA

Before writing a single component, deeply analyze the provided Project Documentation (`README.md`, `PRD.md`, or Spec):
1. **The Core Failure Point:** What mortal or operational danger does this system solve? (e.g. passive uncommitted dashboards where people die vs. confirmed, active commitments).
2. **The Clinical Metaphor:** What physical, biological, or operational entity embodies this problem?
   - Emergency routing → *The Living Commitment Circuit & Response Vector*
   - Cardiology → *Vascular Flow, Synchronized Waveforms & 3D Cardiac Muscle Contraction*
   - Oncology / Radiology → *Volumetric Slice Depth & Spatial Finding Markers*
   - Mass Triage → *Dynamic Casualty Influx Convergence & Strength-Matched Distribution*
3. **The User's Cognitive State:** Healthcare operators are stressed, exhausted, and time-constrained. The interface must communicate **absolute tranquility, politeness, precision, and silence**.

---

## 3. STRICT ANTI-GENERIC AI BLACKLIST (DO NOT USE)

Any interface that looks like a generic AI-generated template has failed. Reject these patterns outright:
- **NO Purple/Blue Gradient Mush:** No generic AI-style violet backgrounds, no neon glow text, no floating random gradient blobs.
- **NO Cliché Medical Icons:** Ban the medical cross, stethoscope, heartbeat squiggle, pill capsules, and generic ambulance emojis. The interface is a serious clinical instrument, not a clip-art website.
- **NO Predictable Layouts:** Ban the standard "left sidebar + top navbar + grid of 4 statistic cards + notification bell" dashboard formula.
- **NO Card-Grid Dependency:** Do not wrap every single piece of data in an identical rounded box with soft drop shadows. Use spatial rails, telemetry strips, floating objects, and unspooling forensic streams.
- **NO Symmetrical 12px Radius on Everything:** Use purposeful geometry — 0px radius for forensic logs and tabular data records, 2px hairlines for circuit rails, and 999px pills only for countdowns and status capsules.

---

## 4. THE LIVING AMBIENT ENVIRONMENT ("QUIET BREATHING")

The interface must never feel like a static page; it must feel **alive, organic, and hyper-smooth**, yet so subtle it is almost subliminal:
1. **Sub-Perceptual Motion (60–120 FPS):** Background features an ultra-slow, breathing spatial coordinate grid (48px) with a soft atmospheric radiance halo.
2. **State-Reactive Ambient Depth:**
   - *Normal state:* Deep slate tranquility (`#0E1518`, `#151F24`). Low ambient motion, wide spatial margins.
   - *Emergency Influx:* The atmospheric halo gently shifts focus toward the active node without abrupt flashing.
   - *Critical Deadline (<=10s):* Ambient vignette tightens subtly; countdown figures gain optical weight with zero layout shift.
   - *Commitment Locked:* A gentle physical settle wave (`1.0 → 1.03 → 1.0`) ripples across the destination node.

---

## 5. NEW INTERACTION PARADIGM: NON-TRADITIONAL SPATIAL SURFACES

Discard static sidebars and top bars in favor of purpose-built control surfaces:
1. **Floating Adaptive Command Dock:**
   - Sits gracefully at the screen top or bottom as a floating glass-slate capsule (`backdrop-blur-xl`, hairline border).
   - Dynamically morphs: when an emergency dispatch or alert is active, it expands with a pulsating countdown capsule allowing instant 1-click focus jump.
   - Houses global environmental tools (audio chime unlocker, live telemetry status, quiet mode toggle).
2. **Contextual Tool Surfaces (No Permanent Clutter):**
   - Actions only appear when an entity is selected or requires intervention.
   - When reviewing a hospital: steppers and toggles only — **zero free text** for emergency speed.
   - When an incoming ambulance request arrives: full-screen takeover with massive **72px tall tactile buttons** separated by ≥24px to eliminate panic mis-taps.
3. **Adaptive Focus Mode:**
   - When an active case or incident is selected, secondary ambient metrics fade to 30% opacity. The screen reorganizes around the critical decision vector.

---

## 6. FUNCTIONAL 3D EXPERIENCES & PHYSICAL DEPTH

Incorporate high-definition 3D and depth **only where it directly explains the clinical state**:
1. **Functional 3D / 2.5D Entities:**
   - *Spatial Radiance Map:* Hospital nodes with dynamic glowing radiance halos whose radius and opacity represent real-time match scores and whose border solidity represents data freshness (solid = fresh, dashed = stale, dotted = unknown).
   - *Living Vehicle / Routing Vectors:* 3D or animated spatial vectors showing the real trajectory between ambulance and emergency bay.
   - *Organ / Anatomical Models:* (If cardiology/imaging) 3D interactive anatomical models highlighting precise affected regions or lead vectors.
2. **Curved Glassmorphism & Tactile Depth:**
   - Deep dark slate grounds with ultra-thin hairlines (`1px solid #33474F`).
   - Narrow physical elevations for locked commitments; retired or superseded cards sink and desaturate.

---

## 7. SIGNATURE MOTION SYSTEM (MOTION IS STATE, NEVER DECORATION)

Every animation must correspond to a real state-machine event:
- **Signal In-Flight:** Dotted, translucent rail with traveling photon pulse.
- **Commitment Locked:** Solid fill sweep (180ms) + terminal physical lock caps + scale settle.
- **Fracture & Auto-Reroute:** The circuit line fractures mid-span (120ms); fragments drift and fade (200ms); the signal automatically re-travels to candidate #2 with **zero manual restart required**.
- **Mass-Casualty Convergence & Split:** 4 casualty tokens converge on the decision point (400ms), hold for matrix solving (250ms), and split outward with animated reason trails to distinct facilities.
- **Forensic Unspooling:** Audit logs unspool downward with staggered rows, expanding into formatted decision-time JSON snapshots.
- **Interpolation:** All numbers interpolate smoothly with tabular mono fonts (`tabular-nums`) to prevent digit jitter.

---

## 8. CLINICAL TYPOGRAPHY & COLOR SCIENCE

Enforce a strict, intentional two-family split:
- **Machine-Measured Telemetry (`IBM Plex Mono` / `SF Mono`):** Every computed number, match score, capability percentage, distance/ETA, countdown, ICU bed count, case ID, and forensic timestamp. Tabular figures enabled (`font-variant-numeric: tabular-nums`).
- **Human Prose (`Inter`):** Hospital names, patient narratives, medical histories, and reasoning strings.
- **The Split Rule:** *Mono = the machine measured it; Sans = a human reads it.*

### Instrument Color Tokens
- Ground: Deep Clinical Slate (`#0E1518`, `#151F24`, `#1C2A31`)
- Signal: Diagnostic Teal (`#3FD2C7` — pending circuit, NOT generic blue)
- Commitment: Locked Emerald (`#5BE38A` — reserved strictly for confirmed commitments)
- Caution: Amber (`#FFB23F` — reroute in progress, stale data)
- Critical: Clinical Red (`#FF4D3D` — reserved strictly for timeouts, rejections, or exhaustion)
- Unknown / Decayed: Muted Slate (`#7C8AA0` — de-weighted freshness)

---

## 9. STEP-BY-STEP IMPLEMENTATION PROCESS

1. **Scaffold & Build Setup:** Vite + React + TypeScript + Tailwind CSS + Lucide Icons + Leaflet (if geospatial) + Web Audio API synthesizer for clinical alarms.
2. **Implement Domain Contract:** Mirror all backend data types, schemas, and enums word-for-word.
3. **Build Living Architecture:** Create the `LivingBackground` spatial grid and floating `CommandDock`.
4. **Implement the Clinical Metaphor:** Build the signature interaction component (e.g. `CommitmentCircuit`, `DistributionBoard`).
5. **Implement Operational Postures:** Build dedicated surfaces (Ambulance, Hospital Console, Oversight Admin, Family Tracker).
6. **Verify 120Hz Smoothness:** Ensure all animations animate only `transform` and `opacity`. Verify `prefers-reduced-motion` fallbacks.
7. **Production Verification:** Run `npm run build` and ensure 0 errors, 0 warnings, and instantaneous multi-device cross-tab synchronization.
```
